## 3. Riesgos y deuda técnica

### 3.1 Modelos sin igualdad por valor

**Crítico estructural.** Los 22 modelos de `lib/shared/models/` carecen de `==`/`hashCode`, no extienden `Equatable` y no usan `freezed`. Como Riverpod compara por identidad de instancia, cualquier reconstrucción (parser de JSON, copy con campo modificado) genera una nueva instancia que invalida providers derivados aunque el contenido sea idéntico.

**Impacto observable:** rebuilds en `DraggableScrollableSheet` del map y en `ListView.builder` de listas grandes cuando `mockDataServiceProvider` u otros providers de datos crudos se vuelven a leer. Hoy el grafo es pequeño y se nota poco; con Supabase y streams reales será un cuello de botella.

**Recomendación:** migración selectiva a `freezed` priorizando `RouteModel`, `StopModel`, `ScheduleModel`, `IncidentModel`, `RouteFeedbackModel`, `RouteSuggestionModel`, `UserModel`, `ActiveTripModel`. El resto puede esperar.

### 3.2 Servicios sin errores tipados

Estado **mixto**. Patrón de referencia (correcto): `lib/data/nfc/nfc_card_service.dart:21-52` declara `enum NfcCardError` + `class NfcCardException implements Exception` + extensión `NfcCardErrorL10n` en `nfc_l10n.dart`. Cumple `ARCHITECTURE.md §4.3`.

**Servicios que incumplen:**

- **`lib/data/mock/mock_data_service.dart:55-60`**: `_loadFromAsset()` no envuelve excepciones. Si `rootBundle.loadString` falla (asset ausente, `PlatformException`) o `json.decode` lanza `FormatException`, el error se propaga crudo. El `ARCHITECTURE.md §4.2` menciona explícitamente que `MockDataException` debería existir; no existe.
- **`lib/data/mock/mock_realtime_service.dart`**: los `Timer.periodic` y `StreamController` no manejan excepciones internas. Si `_interpolateAlongPolyline` (líneas ~214-248) lanza por índice fuera de rango, el stream muere silenciosamente y los consumidores se quedan sin datos sin recibir señal de error.

### 3.3 Llamadas a `print()` restantes

**Limpio.** El lint `avoid_print` activo desde P37 funciona: cero `print(` en `lib/`. El único `debugPrint` legítimo está en `lib/core/utils/app_logger.dart` (wrapper oficial). Cero acciones requeridas.

### 3.4 Lógica de negocio en widgets

**5 sitios flagrantes** con cómputo no trivial dentro de `build()` que debería vivir en providers derivados:

#### 3.4.1 — `home_tab.dart:54-80`: cuatro derivaciones desde currentUser + mockData

```dart
final favRouteIds = user.favoriteRouteIds;        // Set
final habitualStop = mockData.stops.firstWhere(…); // O(n)
final nearbyStops = mockData.stops.where(…)        // O(n)
  .map(…).toList()..sort(…);
final favAlerts = <AlertModel>[];
for (final routeId in favRouteIds) {
  favAlerts.addAll(mockData.getAlertsForRoute(routeId)); // O(k·m)
}
```

#### 3.4.2 — `home_tab.dart:264-274` y `stop_detail_screen.dart:35-40`: inverted index duplicado

Ambos sitios reconstruyen el mapa "qué rutas pasan por una parada" iterando `routeStops.entries`, ignorando que `stopToRouteCodesProvider` ya existe y lo expone memoizado.

#### 3.4.3 — `start_route_screen.dart:44-60`: próximas N salidas

Filtra `schedules` por `routeId` + ordena por `departureTime` + slice de los primeros N. Todo en `build()`.

#### 3.4.4 — `active_route_screen.dart:32-78`: cómputo del estado del trip

Compone `currentIdx`, `nextStop`, `firstStop`, `lastStop` a partir de `routeStops` + `activeTrip` en cada rebuild. Debería ser un value object inmutable expuesto por un provider familia.

#### 3.4.5 — `route_detail_screen.dart:34-43`: cálculo de frecuencia

```dart
final times = schedules.map((s) => _timeToMinutes(s.departureTime)).toList()..sort();
var totalDiff = 0;
for (var i = 1; i < times.length; i++) {
  totalDiff += times[i] - times[i - 1];
}
```

Map + sort + fold dentro del build de la pantalla.

### 3.6 Otros riesgos detectados

#### 3.6.1 — Timers no se pausan en background

`lib/data/mock/mock_realtime_service.dart:47-52` arranca `_tripTimer` (15 s) y `_clockTimer` (1 s) en `init()` y solo los cancela en `dispose()`. No reaccionan a `AppLifecycleState.paused`. Consecuencia: en build release la app mantiene wakelocks pequeños permanentemente mientras esté viva en memoria.

#### 3.6.2 — `assets/mock/comujesa_data.json` ~1.2 MB sin minificar en el APK

El JSON pretty-printed (`json.encode(d, null, 2)`) entra al bundle tal cual. Minificar reduce ~40 %. A futuro debería bajarse del backend con cache local en lugar de bundlearse.

#### 3.6.3 — `google_fonts` con fetch en runtime

No hay `.ttf` en `pubspec.yaml`. `IBMPlexMono` y `DMSans` se descargan al primer arranque desde Google Fonts. Primer paint sin tipografía correcta visible en arranque frío y en goldens. Bloqueador para tests de regresión visual.

#### 3.6.4 — `SmokeBackground` con `Ticker` permanente

`lib/shared/widgets/smoke_background.dart` mantiene un `Ticker` que nunca se detiene aunque la pantalla esté oculta tras un `Sheet` o `Dialog`. En testing fuerza `MediaQuery(disableAnimations: true)`. En runtime no es problema medible.

#### 3.6.5 — `_findClosestRoute` sin early return en polylines vacías

`lib/features/home/tabs/map_tab.dart:60-91` itera `cache.routePathsLod.entries` y accede a `lodData[4] ?? lodData.values.last`. Si una ruta tuviera polyline con 0 puntos, `lodData.values.last` podría estar vacío y el siguiente `points[i]` lanzaría `RangeError`. Hoy todas las rutas tienen ≥ 6 puntos en cada LOD, pero la validación defensiva no existe.

#### 3.6.6 — Sin CI / pre-commit

`flutter analyze` y `flutter test` corren a mano. No hay GitHub Actions, no hay pre-commit hook. Cualquier regresión solo se detecta cuando alguien ejecuta los comandos.
