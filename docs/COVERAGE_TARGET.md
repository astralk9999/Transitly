## Known Blockers

### Remote Layer (~0%)

All `*_remote_repository.dart` files have near-zero coverage because they hit Supabase and cannot be tested without a live backend. Strategies to address:

1. **Abstract Supabase client** behind an interface (injectable mock).
2. **Integration test target** against a local Supabase or staging instance.
3. **Accept 0% on remote layer** and compensate with higher coverage in mock/local/repository-provider layers.

### Widget Tests Fidelity

Widget tests are slow and flaky without real rendering. The current suite (60 test files) covers design system components and shared widgets. Screen-level coverage needs per-screen pump tests.

## How to Measure

### Quick check (bash)

```bash
tool/verify_state.sh
```

Prints a coverage line auto-extracted from `coverage/lcov.info`.

### Full measurement

```bash
flutter test --coverage
```

Generates `coverage/lcov.info`. Parse with any LCOV-compatible tool:

```bash
# Using genhtml (Linux/macOS)
genhtml coverage/lcov.info -o coverage/html

# Using lcov summary
lcov --summary coverage/lcov.info

# Manual line-based (bash)
awk -F'[:,]' '/^DA:/ {t++; if($3>0) h++} END {printf "%.2f%%\n", h/t*100}' coverage/lcov.info
```

### Per-file drill-down

```bash
lcov --list coverage/lcov.info | grep -E "data/operator|core/"
```

### CI Integration

The `tool/verify_state.sh` script is already integrated into the verification workflow. Coverage is extracted and displayed in the auto-generated state block.
