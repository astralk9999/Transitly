## 2. Auditoría con causa raíz (archivo:línea)

### Bug 1 — Widgets no se actualizan al cambiar config

**Auditado:**
- `WidgetDataWriter.writeNextBus/writeMyLineStatus/writeNfcBalance` (`lib/data/widgets_native/widget_data_writer.dart`) escriben a `SharedPreferences` y llaman `HomeWidget.updateWidget()`.
- `_widgetBackgroundCallback` en `main.dart:286+` los llama SOLO desde el WorkManager periódico.
- **NO existe ningún hook** en `home_habitual_config_provider.dart`, ni en `user_favorites_provider.dart`, ni en el flujo de escaneo NFC normal (`NfcScanNotifier.startScan` SÍ lo hace ya), que dispare `WidgetDataWriter.*` al cambiar la config.

Resultado: el widget muestra el estado del último periodic worker (15 min mínimo), no el actual.

### Bug 2 — Widgets feos
Los 3 layouts XML (`widget_next_bus.xml`, `widget_my_line.xml`, `widget_nfc_balance.xml`) usan:
- Fondo plano (`widget_bg.xml` con color sólido).
- Tipografía system default (`textStyle="bold"` para route_code, nada para el resto).
- Sin badge de color de línea, sin iconos, sin acentos.

### Bug 3 — Login Google roto
`auth_repository_supabase.dart:139-145`:
```dart
final googleSignIn = GoogleSignIn(
  scopes: const ['email', 'profile'],
  serverClientId: webClientId,
);
await googleSignIn.signOut();
```
Después llama `signInWithIdToken`. Hipótesis del fallo:
- `google_sign_in` plugin tiene API breaking en `^7.x`: `GoogleSignIn(...)` constructor cambió.
- El `serverClientId` ahora se pasa via `GoogleSignIn.initialize()`.
- Verificar versión real en pubspec y migrar si es 7.x.

### Bug 4 — Rate limit error sin traducir
`lib/data/auth/auth_helpers.dart:6-27` — `mapAuthError` solo cubre 4 errores conocidos. El "For security purposes, you can only request this after X seconds" cae en el genérico `AuthError.unknown` y se muestra crudo. Falta el caso del rate limit.

### Bug 5 — Verificación email + link localhost
Dos partes:
1. **Sin aviso**: `signin_screen.dart` / `signup_screen.dart` muestran "creado" pero no un mensaje claro "revisa tu email para verificar".
2. **Link localhost**: viene del Site URL configurado en Supabase Dashboard → Authentication → URL Configuration. Probablemente `http://localhost:3000` (default). Hay que cambiarlo a un esquema que abra la app (`transitly://auth/verify`) y emparejarlo con el template del email.

### Bug 6 — Magic link rate limit
Mismo origen que Bug 4. `signInWithOtp` también devuelve `over_email_send_rate_limit`.

### Bug 7 — Alto contraste no mejora visibilidad
`lib/core/theme/high_contrast_theme.dart:11`:
```dart
final solidScheme = TransitColorScheme.of(isDark);
```
Esto solo coge el scheme **estándar** (dark/light), ignora el scheme custom del usuario y **no fuerza textHi a blanco/negro puro**. Solo cambia bordes y opacidades.

Resultado: en modo claro la letra queda gris-medio sobre fondo claro = invisible.

### Bug 8 — Personalización no persiste
Auditoría parcial: `theme_notifier.dart:170-182` los setters de `backgroundId/backgroundEnabled/opacity` llaman `unawaited(_persist())`. Eso PERSIST en local. Pero **al reabrir, `loadGuest()` se llama incondicionalmente si la sesión es null**.

Si el usuario era invitado, sus prefs se cargan de la box `guest_prefs`. Si por algún cambio de versión de Hive el contenido se corrompe, defaults aparecen.

Otra hipótesis: el flujo nuevo de `Supabase.initialize` con `authFlowType: pkce` cambió el comportamiento del listener `onAuthStateChange`. Si emite `signedOut` falsamente al boot, dispara reset.

Necesita logs reales para confirmar; mientras tanto fix defensivo: verificar que `loadGuest()` NO sobreescriba si Hive ya tiene datos.

### Bug 9 — Cambiar fondo no aplica
`theme_notifier.dart:170-175`:
```dart
set backgroundId(String value) {
  if (_backgroundId == value) return;
  _backgroundId = value;
  notifyListeners();
  unawaited(_persist());
}
```
Llama `notifyListeners()`. Si el `BackgroundWrapper` no escucha al notifier correctamente o tiene un `ConsumerWidget` que no se invalida, no se actualiza visualmente.

Probable: en sesión previa cambiamos `background_wrapper.dart` para usar `themeNotifierProvider` directamente. Si el watch ahora es `ref.watch(themeNotifierProvider.select((n) => n.background))` y la selección no detecta el cambio de `_backgroundId` (porque `background` getter usa `backgroundFromId` que crea instancias nuevas), el wrapper no rebuild.

Verificable con un `print` en el switch del wrapper.

### Bug 10 — Líneas no se ven en mapa
`map_tab.dart:57-110` `_filteredRoutes` aplica varios filtros:
- `_serviceTypeFilter`: si está seteado a un tipo, filtra TODO al activar otro tipo
- `!f.showOfficial && !f.showCommunity`: la guarda "defensivo" deja pasar, pero...
- `f.onlyFavorites`: si está activo y no hay favs → vacío
- `f.disabledOperators` / `f.disabledKinds`: si pre-rellenados con todos los valores → vacío

Probable causa: persistencia del `MapFilterController` mantiene state corrupto entre sesiones. Audit pendiente.

Otra causa: el `routeStopsMap` o `routePathsLod` no se calcula bien tras una invalidate.

### Bug 11 — Mejorar Explorar comunidad
`community_routes_screen.dart` existe pero el usuario la considera pobre. Audit visual pendiente; presumiblemente falta filtros, search, ordenamiento, badges, etc.

### Bug 12 — Filtros mapa: zonas
`map_filter_controller.dart` tiene `disabledOperators` y `disabledKinds`. Falta `disabledZones` + UI para listar zonas conocidas (Jerez, Cádiz, etc.) y desactivarlas.

### Bug 13 — Avisos distancia
`home_alert_item.dart:66`:
```dart
'${alert.radiusMeters!.toInt()}m alrededor de zona'
```
Eso es el **radio** de la zona afectada (configurado al crear el aviso, ej. 3 km), no la **distancia del usuario**. El usuario lo confunde con "estoy a 3 km".

Solución:
- Renombrar a "Zona de 3 km a la redonda" (claro).
- Opcional: calcular la distancia real del usuario (`Distance().as(...)` desde `userLocationLatLngProvider`) y mostrarla aparte.

### Bug 14 — Nav bar cortado en rotación
`home_bottom_nav.dart:42-45`:
```dart
SafeArea(
  top: false,
  child: SizedBox(height: 56, child: ...),
)
```
`SafeArea` por defecto respeta safe areas LATERALES también. Pero el `Container` padre no aplica padding lateral en notch. En landscape con cámara frontal, el contenido queda cortado.

Además, `home_shell.dart:77-83` decide `useRail` por aspect ratio. Si en landscape se ejecuta `useRail = true` pero el `HomeBottomNav` aún aparece en algún branch, hay solape.

### Bug 15 — Saludo no contextual
`home_tab.dart:163-168` SÍ hace `DateTime.now().hour` y elige saludo. Funciona técnicamente.

Hipótesis del usuario: rangos no le encajan ("buenas tardes" desde las 12 hasta las 20 le parece raro). O el `Builder` no se rebuild al cambiar de hora mientras la app está abierta.

Fix: ampliar lógica a "buenos días" hasta las 14, "buenas tardes" 14-21, "buenas noches" después. Y opcionalmente añadir "buena madrugada" antes de las 6.

## 8. Riesgos

- **R1: Migración google_sign_in 6→7 puede tener otras breaking changes.** Mitigación: leer changelog completo antes de migrar.
- **R2: Cambiar Site URL en Supabase puede romper enlaces ya emitidos.** Mitigación: cambiar solo en dev primero; verificar email entrante.
- **R3: Reset de filtros pierde state del usuario.** Mitigación: botón con confirmación explícita.
- **R4: Modificar `HighContrastTheme` puede romper otras pantallas.** Mitigación: smoke test en todas las tabs.
- **R5: Hook de sync en `UserFavoritesNotifier` puede causar loops si el writer modifica state.** Mitigación: el writer es write-only, no toca providers.
- **R6: Widgets en Android tardan ≥30s en reflejar `HomeWidget.updateWidget()`.** Mitigación: documentar timing real; añadir `RemoteViews.invalidateAll` si es necesario.

## 9. Criterios de aceptación

1. Configurar viaje habitual → widget muestra el nuevo en < 10s sin reabrir app.
2. Escanear NFC → widget saldo refleja al instante.
3. Login Google → entra a `/home/inicio` sin errores.
4. Crear cuenta → dialog "Hemos enviado email" → email recibido → tap link → vuelve a la app verificado.
5. Rate limit: SnackBar "Demasiados intentos. Inténtalo en 32s." (no inglés).
6. Modo claro + alto contraste: texto negro puro sobre fondo blanco puro.
7. Cambiar paleta → cerrar app → reabrir → paleta intacta.
8. Cambiar fondo en Apariencia → fondo aplicado al salir.
9. Abrir mapa → líneas visibles. Si no, botón "Restablecer filtros" funciona.
10. Filtros → sección "Zonas" → desactivar Jerez → routes COMUJESA ocultos.
11. Avisos: texto "Afecta 3 km a la redonda" (no "3000 m alrededor").
12. Explorar comunidad: buscar, filtrar, ordenar funcionales.
13. Rotar móvil a landscape: nav bar desaparece (NavRail aparece) sin recorte.
14. Saludo a las 7:00 = "Buenos días". A las 16:00 = "Buenas tardes". A las 22:00 = "Buenas noches". A las 3:00 = "Buena madrugada".
