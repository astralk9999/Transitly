# Sub-plan B de P0 — Mapa: líneas visibles + estabilidad tras tiempo/cambio de pestaña

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cerrar dos blockers P0 del plan V16 que afectan al mapa principal: (P0-01) las líneas de COMUJESA no aparecen al abrir el mapa; (P0-02) el mapa deja de cargar tras minutos abierto o al cambiar de pestaña y volver.

**Architecture:** Los dos bugs son independientes pero comparten la misma pantalla (`MapTab` + `TransitMap` + `MapDataCache`).

P0-01 — `MapDataCache._buildFromRepos` (`map_data_cache.dart:89`) construye el cache desde `routesBox` de Hive cuando hay sesión Supabase. Si la box todavía no se hidrató (sesión nueva, sin sync previo) el cache queda vacío y `buildRoutePolylines` skipea todas las rutas por falta de paths/stops. Solución: si `routesBox.values` está vacío, hacer fallback al builder mock — así las líneas se pintan siempre, y cuando los datos reales lleguen el provider se invalida y reemplaza.

P0-02 — `_MapTabState` no usa `AutomaticKeepAliveClientMixin`. Cada cambio de pestaña en el navbar destruye el state, dispose del `MapController` y reconstruye todo. Combinado con el `FMTCTileProvider` que es un singleton compartido entre pantallas y un cache de tiles ObjectBox que va acumulando estado, tras varios ciclos las tiles dejan de aparecer. Solución triple: (a) keep-alive en `MapTab` para preservar el state entre cambios de pestaña, (b) listener de lifecycle que invalide el provider FMTC si la app pasó >5 min en background, (c) breadcrumbs Sentry en initState/dispose para verificar el comportamiento real en runtime.

**Tech Stack:** Flutter `flutter_map` 7.0.2 + `flutter_map_tile_caching` 10.0.0, Riverpod 2.6.1, Hive 2.2.3, Supabase Auth, Sentry breadcrumbs.

import 'package:transitly/features/map/map_data_cache.dart';
import 'package:transitly/shared/models/route_model.dart';

void main() {
  setUpAll(() async {
    TestWidgetsFlutterBinding.ensureInitialized();
    final dir = await Directory.systemTemp.createTemp('hive_mapcache_test_');
    Hive.init(dir.path);
  });

  test('cache uses mock data when routesBox is empty even with auth session',
      () async {
    final mockData = await MockDataService.init();
    expect(mockData.routes, isNotEmpty,
        reason: 'precondition: mock data must have routes for this test');

    // Open an empty routes box to simulate "session exists but Hive not synced yet"
    final boxName = 'routes_test_empty_${DateTime.now().microsecondsSinceEpoch}';
    final emptyRoutesBox = await Hive.openBox<RouteModel>(boxName);

    final container = ProviderContainer(
      overrides: [
        mockDataServiceProvider.overrideWithValue(mockData),
        // Force authenticated path by overriding the supabase client provider
        // with a fake that reports a session — we route through that branch
        // in map_data_cache and validate the fallback.
        routesBoxProvider.overrideWithValue(emptyRoutesBox),
        supabaseClientProvider.overrideWith(
          (ref) => throw UnimplementedError(
              'supabase client should not be needed for this fallback test'),
        ),
      ],
    );
    addTearDown(container.dispose);

    // Even with an "authenticated" path, when routesBox is empty the cache
    // should fall back to mock data so the map can render.
    final cache = container.read(mapDataCacheProvider);

    expect(cache.routeMap, isNotEmpty,
        reason: 'fallback to mock should populate routeMap');
    expect(cache.routePathsLod, isNotEmpty,
        reason: 'fallback to mock should populate routePathsLod');
    expect(cache.routeStopsMap, isNotEmpty,

```dart
final mapDataCacheProvider = Provider<MapDataCache>((ref) {
  final routesBox = ref.watch(routesBoxProvider);
  if (routesBox.isEmpty) {
    // Sesión nueva sin sync previo, o modo invitado. Servimos mock para que
    // el mapa pinte líneas desde el primer frame; el provider se invalida
    // cuando llega el primer batch de rutas a Hive y se reconstruye con
    // datos reales.
    return _buildFromMockData(ref);
  }

  final client = ref.watch(supabaseClientProvider);
  final session = client.auth.currentSession;
  if (session == null) {
    return _buildFromMockData(ref);
  }

  return _buildFromRepos(ref);
});
```

  DateTime? _lastBackground;

  @override
  void didChangeAppLifecycleState(AppLifecycleState state) {
    if (state == AppLifecycleState.paused) {
      _lastBackground = DateTime.now();
    } else if (state == AppLifecycleState.resumed) {
      final bg = _lastBackground;
      _lastBackground = null;
      if (bg != null && DateTime.now().difference(bg).inMinutes >= 5) {
        // Tras 5+ minutos en background el TileLayer puede haber perdido
        // tiles y los stores ObjectBox del FMTC pueden estar en mal estado.
        // Forzamos un ciclo de bypass para que el siguiente build pida tiles

        if (mounted) {

            _bypassFmtcUntil =
                DateTime.now().add(const Duration(seconds: 5));
          });
        }
      }
    }
  }

## Notas y consideraciones

**Sobre el fallback de `_buildFromMockData`.** El builder mock ignora completamente la sesión Supabase. Esto es coherente con la decisión V16 de "data offline-first": el mock seed siempre es válido y se sobrescribe cuando llegan datos reales. La invalidación del provider es automática gracias a `ref.watch(routesBoxProvider)` — cuando el box recibe inserts, el provider se reconstruye.

**Sobre `AutomaticKeepAliveClientMixin`.** El comportamiento de `StatefulNavigationShell` de go_router preserva los `Navigator`s de cada branch, pero NO necesariamente los States internos según condiciones de reconstrucción. El mixin garantiza preservación determinista.

**Sobre Sentry breadcrumbs.** Solo se añaden si Sentry está activo (depende de `dart-define` SENTRY_DSN). En guest mode sin consent no se reportan eventos — los breadcrumbs solo quedan en el buffer local y se envían si hay error.

**Sobre los 5 minutos de background.** Valor empírico. Si el usuario reporta que el problema se manifiesta antes, bajar a 2 min. Si nunca se manifiesta, considerar simplemente eliminar el bypass automático.

**Sobre los warnings del linter.** El uso de `WidgetsBindingObserver` desde un `State` con mixin requiere que `super.dispose()` se llame al final y `super.build(context)` al principio del build. Si el linter da warnings sobre orden, son falsos positivos y se ignoran.
